Data shelf beacon

Slipgate ships no game data, so every device needs the player's own files. A data shelf on a NAS serves the devices at home; this is how it serves the ones that are not, without anyone retyping a hostname after a reboot.

How it works

  1. serve-shelf.py runs on the NAS, listening on localhost only and refusing every request that does not carry the shelf key.
  2. A tunnel — cloudflared or ngrok — puts it on the public web over TLS. A quick tunnel gets a new hostname each time it starts, which is the whole reason for the step below.
  3. The NAS publishes a pointer to this site: where the shelf is now, and the key to read it. The app is configured with the beacon address, which never changes.

One field in Settings, set once per device. After a power cut the NAS republishes and every device follows it without being touched.

Boot the shelf

The scripts live in the Slipgate repository under tooling/data-shelf. Lay the files out one directory per gate, with the Quake-family engines' own directories inside theirs and map packs in addons: 

slipgate-server/
  mars/doomu.wad
  corvus/heretic.wad
  korax/hexen.wad
  macil/strife1.wad
  chthon/id1/pak0.pak
  addons/hexdd.wad

Then write the configuration and start it:

export SLIPGATE_SHELF_ROOT=/volume1/games/slipgate-server
export SLIPGATE_SHELF_KEY=$(openssl rand -hex 16)
export SLIPGATE_TUNNEL=cloudflared
export SLIPGATE_BEACON_URL=https://<this-site>/beacon/<beacon-id>
export SLIPGATE_BEACON_TOKEN=<publish-token>

tooling/data-shelf/publish-shelf.sh

The beacon id is 24 to 64 hex characters that you choose once — it is the read credential, so generate it with openssl rand -hex 16 rather than picking a word. The publish token is the site's SLIPGATE_BEACON_TOKEN environment variable.

The beacon

Request Who calls it What happens
POST /beacon/<id> The NAS Stores the pointer. Needs the publish token as a bearer token.
GET /beacon/<id> The app Returns the pointer, uncached. Knowing the id is the credential.
DELETE /beacon/<id> You Forgets the pointer, so the app stops being sent anywhere.

A pointer is four lines, tab separated, because the app parses it without a JSON parser:

slipgate-beacon 1
url	https://tunnel-hostname.example
key	9f0c1d2e3a4b5c6d7e8f9a0b1c2d3e4f
updated	2026-08-20T18:22:41Z

What this is not

Not a way to get game data you do not own, and not a public mirror: a tunnelled shelf refuses anonymous requests, and the pointer that unlocks it is only readable by whoever holds the beacon id. Serving commercial IWADs to strangers is redistribution however briefly it is done, which is why the key is not optional and the tunnel hostname alone opens nothing.
